# Frontend — GitHub Pages

หน้าเว็บสำหรับเจ้าหน้าที่ภาคสนามของ
**ระบบบันทึกจำนวนรถยนต์ลานจอดรถ ช่วงงานพิธีพระราชทานปริญญาบัตร**

คู่มือฉบับเต็มอยู่ใน `../README.md`

---

## ⚠️ สิ่งเดียวที่ต้องแก้ก่อนใช้งาน

เปิด `config.js` แล้วใส่ Web App URL ของ Google Apps Script:

```js
API_URL: "https://script.google.com/macros/s/AKfycb.........../exec",
```

- ต้องลงท้ายด้วย `/exec` (ห้ามใช้ `/dev` เพราะจะบังคับให้ผู้ใช้ล็อกอิน)
- **ห้ามใส่ Spreadsheet ID, Client Secret, รายชื่อผู้ดูแล, API key หรือ secret ใด ๆ ในโฟลเดอร์นี้**
  ทุกไฟล์ที่นี่เป็นสาธารณะบน GitHub
- **Google Client ID ก็ไม่ต้องใส่ที่นี่** — หน้าเว็บขอจากระบบหลังบ้านเองตอนเปิดหน้า
  (action `getAuthConfig`) จึงมีจุดตั้งค่าเพียงจุดเดียวคือ `setupAuthentication()` ใน Apps Script

## การนำขึ้น GitHub Pages

1. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ไว้ที่ **ราก** ของ repository
   (`index.html` ต้องอยู่ที่รากเสมอ)
2. **Settings → Pages** → Source: *Deploy from a branch* → Branch: `main` / `(root)` → Save
3. รอประมาณ 1–2 นาที แล้วเปิด URL ที่ได้

ไม่มี build step ไม่มี npm ไม่มี framework — เป็น HTML/CSS/JavaScript ล้วน
เปิดจากไฟล์บนเครื่องเพื่อทดสอบก็ได้ (ยกเว้น Service Worker ที่ต้องใช้ HTTPS หรือ localhost)

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเดียว 4 มุมมอง: บันทึกข้อมูล / ข้อมูลล่าสุด / แดชบอร์ด / ผู้ดูแลระบบ |
| `styles.css` | ธีมน้ำเงิน-ทอง Mobile First, contrast สูง สำหรับใช้งานกลางแจ้ง |
| `config.js` | **ไฟล์ที่ต้องแก้** — API_URL และค่าตั้งค่าที่ไม่ใช่ความลับ |
| `utils.js` | DOM, วันที่แบบไทย, ตรวจข้อมูล, localStorage, CSV, toast |
| `auth.js` | **ใหม่ 1.2.0** — ห่อ Google Identity Services · เก็บ token ในหน่วยความจำเท่านั้น |
| `api.js` | ชั้นเชื่อมต่อ Apps Script · อ่านสาธารณะ = GET/JSONP · คำขอที่มี token = POST เท่านั้น (ไม่มี JSONP สำรอง) + แปล error เป็นภาษาไทย |
| `app.js` | หน้าบันทึกข้อมูล, การนำทาง, สถานะการเชื่อมต่อ |
| `dashboard.js` | หน้าข้อมูลล่าสุด และแดชบอร์ด (KPI, ตาราง, Ranking, Zone, Time Trend) |
| `admin.js` | หน้าผู้ดูแล: ประวัติ, จัดการลานจอด, จัดการวันงาน, จัดการปี, ตรวจสอบระบบ |
| `manifest.webmanifest` · `icon.svg` | ติดตั้งเป็นแอปบนหน้าจอโฮมของมือถือได้ |
| `sw.js` | Service Worker — แคช **เฉพาะไฟล์หน้าเว็บ** ไม่แตะคำขอ API เด็ดขาด |

## สิ่งที่ห้ามแก้ (จะทำให้ระบบพังบนมือถือจริง)

1. **ห้ามเปลี่ยน `Content-Type` ใน `api.js` เป็น `application/json`**
   และห้ามเพิ่ม custom header — จะเกิด CORS preflight ซึ่ง Apps Script ตอบไม่ได้
2. **ห้าม hard-code รายชื่อลานจอดใน `index.html` หรือ `app.js`**
   รายการลานต้องมาจาก API เสมอ เพื่อให้เพิ่มลานปีถัดไปได้โดยไม่ต้อง deploy ใหม่
3. **ห้ามให้ `sw.js` แคชคำขอไปยัง `script.google.com`** — จะทำให้เห็นข้อมูลเก่า
   หรือเกิดการส่งข้อมูลซ้ำ
4. **ห้ามเก็บ Google ID Token ที่ใดนอกจากหน่วยความจำของหน้าเว็บ**
   ห้ามเก็บใน `localStorage` / `sessionStorage` / cookie / URL และห้าม `console.log` ออกมา
5. **ห้ามให้คำขอที่แนบ token ถอยไปใช้ JSONP** — JSONP บังคับให้ข้อมูลอยู่ใน URL
   ซึ่งทำให้ token รั่ว ปล่อยให้คำขอล้มเหลวไปเลยดีกว่า
6. **ห้ามให้หน้าเว็บเป็นผู้ตัดสินว่าใครเป็นผู้ดูแล** — `isAdmin` ที่ได้จาก API
   ใช้เพื่อ *แสดงผล* เท่านั้น สิทธิ์จริงตัดสินที่เซิร์ฟเวอร์ทุกคำขอ
5. **ห้ามแสดงข้อความ "บันทึกสำเร็จ" ก่อนได้รับ `success: true` จาก Backend**
6. **ห้ามแสดงวันงานที่ `isOpenNow` เป็น false ให้ผู้ใช้เลือก** และห้ามตัดสินใจเรื่อง
   ช่วงเวลาด้วยนาฬิกาของเครื่องผู้ใช้ — ต้องใช้ค่าที่เซิร์ฟเวอร์ส่งมาเท่านั้น
   (นาฬิกาเครื่องผู้ใช้ตั้งผิดได้ และเซิร์ฟเวอร์เป็นผู้ตัดสินอยู่แล้ว)

## ลำดับการใช้งานของเจ้าหน้าที่ภาคสนาม (เวอร์ชัน 1.2.0)

หน้าบันทึกถูกจัดเป็นขั้นตอนที่มีเลขกำกับ เพื่อลดโอกาสเลือกผิดลานและผิดวัน

0. **ลงชื่อเข้าใช้ด้วยบัญชี Google** — การ์ดอยู่บนสุดของหน้า ปุ่มบันทึกจะกดไม่ได้จนกว่าจะลงชื่อเข้าใช้
   ใช้บัญชี Google อะไรก็ได้ ไม่จำกัดโดเมน และไม่ต้องขึ้นทะเบียนล่วงหน้า
1. **เลือกปี** — เป็นปุ่มใหญ่ · **ปีจะเป็นสีจางกดไม่ได้เฉพาะเมื่อผู้ดูแลปิดรับข้อมูลของปีนั้น**
   ปีที่ยังไม่ถึงวันงานหรือพ้นวันงานแล้ว **ยังกดได้** เพื่อดูข้อมูลย้อนหลัง
2. **เลือกวันงาน** — แสดงเฉพาะวันที่ **บันทึกได้ ณ เวลานั้นจริง ๆ**
   ไม่แสดงวันที่ยังไม่ถึงและวันที่ผ่านไปแล้ว หน้าเว็บตรวจสอบซ้ำทุก 60 วินาที
   และเมื่อกลับมาที่หน้าเว็บอีกครั้ง รายการจึงเปลี่ยนเองเมื่อถึงเวลาโดยไม่ต้องโหลดหน้าใหม่
3. **เลือกลานจอดรถ** — กดปุ่มลูกศรเพื่อเปิดดูรายการทั้งหมด หรือพิมพ์ค้นหาจาก
   ลำดับลาน / ชื่อลาน / โซน ก็ได้
4. **กรอกจำนวนรถ** แล้วจึงตรวจชื่อผู้บันทึก (เติมจากบัญชี Google ให้อัตโนมัติ แก้ไขได้)
   เบอร์โทร และหมายเหตุ — **ไม่มีช่องกรอกอีเมลอีกต่อไป**

ระหว่างกรอก **การ์ด "ลานที่กำลังบันทึก" จะติดอยู่ใต้แถบเมนูตลอดเวลา**
แสดงเลขลานตัวใหญ่ ชื่อเต็มของลาน โซน ความจุ และวันงาน
และเมื่อกดบันทึกจะมีกล่องยืนยันย้ำอีกครั้งว่ากำลังบันทึกลานใด วันใด จำนวนเท่าใด

> **หมายเหตุเรื่องอีเมล (เปลี่ยนในเวอร์ชัน 1.2.0):** อีเมลมาจากบัญชี Google
> ที่ยืนยันแล้วเท่านั้น ระบบไม่รับอีเมลที่หน้าเว็บส่งมาเอง
> รองรับทุกโดเมน (รวมถึง รปภ. Outsource ที่ใช้ Gmail) ไม่บังคับว่าต้องเป็น `@mahidol.ac.th`

## การออกแบบสำหรับใช้งานภาคสนาม

- ช่องกรอกและปุ่มสูงอย่างน้อย 50px, ปุ่มบันทึกสูง 56px
- ช่องจำนวนรถใช้คีย์บอร์ดตัวเลข ตัวอักษรใหญ่พิเศษ และกรองอักขระที่ไม่ใช่ตัวเลขทิ้งทันที
- เบอร์โทรใช้คีย์บอร์ด `tel`
- ช่องเลือกลานจอดค้นหาได้ทั้ง **ลำดับ / ชื่อลาน / โซน** (เช่น `24`, `อาคารเจรจา`, `Zone E`)
  รองรับลูกศรขึ้น-ลง, Enter, Escape และ `aria-*` สำหรับโปรแกรมอ่านหน้าจอ
- สถานะทุกอย่างสื่อด้วย **ข้อความ + สี** ไม่ใช้สีเพียงอย่างเดียว
- เมื่อกรอกผิด ระบบเลื่อนหน้าจอและโฟกัสไปยังช่องที่ผิดโดยอัตโนมัติ
- โหมด **"บันทึกต่อเนื่อง"** คงปี วันงาน และข้อมูลผู้กรอกไว้ ล้างเฉพาะลานจอดและจำนวนรถ
- ตัวเลือก **"จำข้อมูลผู้กรอกในอุปกรณ์นี้"** เก็บ **ชื่อและเบอร์โทร** ไว้ใน `localStorage`
  เฉพาะเมื่อผู้ใช้ติ๊กเท่านั้น และลบทันทีเมื่อเอาติ๊กออก
  (เวอร์ชัน 1.2.0 ไม่เก็บอีเมลแล้ว เพราะมาจากบัญชี Google อยู่แล้ว)
- เมื่อการลงชื่อเข้าใช้หมดอายุระหว่างกรอก **ข้อมูลในฟอร์มไม่หาย** — ลงชื่อเข้าใช้ใหม่แล้วกดบันทึกต่อได้ทันที
